## 核心发现：确认滞后型未来函数

缠论的**分型需要右侧 K 线确认、笔端点在出现反向分型前会持续被替换**，因此 `signal.date = 笔终点日` 的信号在该日实盘根本不可得，按该日撮合属于未来函数。

修复方式（本仓库已实现为引擎默认）——**逐日确认制**：

1. 买点：对每个交易日 t，仅用截至 t 的 K 线重新计算（逐日截断），信号首次出现的日期才是实盘可得日
2. 剔除「幻影信号」：全历史分析里存在、但逐日截断下不会出现的信号（实测占买点 **24.8%**）

| 口径 | 年化 | 夏普 | 回撤 | 买入笔数 |
|---|---|---|---|---|
| 严格等确认（本仓库默认） | +2.05% | −0.15 | 5.55% | 103 |
| 分型确认即买（含幻影，不可实现） | +6.83% | +0.64 | 6.21% | 127 |
| 先开后验（chan.py 方案） | +2.72% | −0.07 | 2.64% | 189 |

## 方法论：技术策略的 6 道验收门槛

见 `tools/acceptance.py`（一条命令输出结论）：

1. **确认滞后检查**——信号在其日期是否真实可得（幻影信号率）
2. **成本敏感**——0% / 0.1% / 0.3% 滑点三档
3. **β 对照（硬门槛）**——必须显著超越同池等权持有
4. **样本外**——开发/验证分段
5. **统计显著性**——打乱信号日期的蒙特卡洛置换检验
6. **多重检验**——试验计数 + Bonferroni/BH 校正（防数据挖掘）
