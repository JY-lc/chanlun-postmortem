# 开源缠论量化项目调研：它们如何处理"信号延后 / 实盘不可用"问题
**2026-09-10 · 调研对象：GitHub 主流缠论开源项目（README + 参数文档原文）**

## 二、核心发现：**它们都知道这个问题，处理方式分四类**

### 类型1️⃣ 区分"事后结构点"与"当下可执行点"，并明确承认延后（chan.py）

chan.py 把买卖点分成两类，README 原文：

> **bsp**（形态学买卖点）：回看历史结构算出的标准买卖点
> **cbsp**（自定义动力学买卖点）："该策略类在每根新K线出现时判断当下是否是新的买卖点（**即仅有到当下为止的K线数据**），**一般而言，相较于 bsp 会延后，而且不一定正确**"

→ **这与我们发现的问题完全一致**（我们说"确认滞后型未来函数"，他们叫"cbsp 相较于 bsp 会延后且不一定正确"）。
→ 注意：他们的 bsp 是"事后结构"，如果直接拿 bsp 回测，就是我们踩的坑；**官方文档明确警告了这个差异**。

### 类型2️⃣ 严格开仓：当下无法执行就放弃（chan.py，默认开启）

> `strict_open`：**严格开仓条件，即如果对一个买卖点当下无法找到合适的买卖时机却已经完成一笔了，就放弃。默认为 True。**
> `judge_on_close`：**根据K线收盘价来作为开/平仓指标，默认为 True（否则当天K线某一时刻突破了信号阈值即会交易）**
> `only_judge_last`：只计算最后一根K线的买卖点（用于实盘/选股）

- `strict_open` = 我们的**"幻影信号剔除"**（不可执行的信号不交易）——同一思路，他们做成了默认开关
- `judge_on_close` = 我们的**"收盘后确认、次日执行"**——避免盘中瞬时突破的不确定性（另一种未来函数）

### 类型3️⃣ 逐Bar增量计算：信号只反映"截至当下"（chanlun-pro、czsc）

chanlun-pro README 原文：

> "缠论数据的计算，采用**逐Bar方式**进行计算…再根据**下一根K线数据，更新**以上缠论数据；**如已经是形成并确认的分型、笔、线段、中枢等，后续无特殊情况，则不会进行变更**。
> 程序会给出当下的一个背驰或买卖点信息，**至于后续行情如何走，有可能确认，也有可能继续延续，最终背驰或买卖点消失**；这种情况就需要通过其他的辅助加以判断，如均线、布林线等指标，也可以看小级别的走势进行判断，以此来增加成功的概率。"

→ **"买卖点可能消失" = 我们的"幻影信号/未定型"**。他们的应对是"用其他指标辅助提高概率"，**没有解决收益损失**。

czsc 的架构同理：`generate_czsc_signals(bars, signals_seq)` 是**顺序生成信号序列**（天然无前视），再用 `WeightBacktest` 消费信号做权重回测——**这个"信号与回测解耦、信号顺序生成"的架构，正是无偏回测的正确形态**（等于我们的确认制思想）。

### 类型4️⃣ 线上线下一致性校验（chan.py，最专业的做法）

chan.py 提供了专用工具 `FeatureReconciliation.py`，README 原文：

> "如果担心接入后**线上模型和离线模型特征不一致**带来的差异（**比如 backtest.py 中笔段的计算起始时间和实盘中的不一样，可能会导致某些特征不相等**），可以运行 `FeatureReconciliation.py` 来进行特征一致性检查"

→ 他们官方承认：**"回测中的笔段计算起始时间与实盘不同"会导致不一致**——这就是我们发现问题的另一种表述（窗口/起点不同→结构不同→信号不一致）。他们用工具**校验**，而不是消除。

## 三、与我们做法的对比

| 问题 | 开源项目的做法 | 我们的做法 |
|---|---|---|
| 信号"延后" | 承认（cbsp 会延后）；`strict_open` 放弃不可执行信号 | **逐日截断确认制**：精确算出每个信号的"实盘可得日"，剔除幻影信号 |
| 结构"随窗口变化" | `FeatureReconciliation` 一致性校验 | 交叉验证（推导 vs 逐日截断重跑，14/18 完全一致） |
| 盘中突破的不确定性 | `judge_on_close=True`（用收盘价判断） | 收盘后计算 + T+1_open 执行 |
| **收益影响** | ❌ **无人量化**（没有β对照、成本、样本外） | ✅ 完整归因：16.79% → 2.05%，≈池子β（2.01%） |

**关键差异：开源项目知道"信号会延后/消失"，但它们大多不做严格的收益归因**——所以它们既不知道也不关心"这个信号体系到底赚不赚钱"。我们把这个验证做完了，结论是**它不赚钱（≈β）**。

## 四、可以直接借鉴的三个具体机制

1. **`strict_open`（不可执行信号直接放弃）** → 我们已有等价实现（幻影剔除），可再加"执行时点不可行则跳过"
2. **`judge_on_close`（收盘价判断）** → 我们已是这么做的，建议固化为配置项并在文档标注
3. **特征一致性校验（`FeatureReconciliation`）** → 我们可扩展 `tools/acceptance.py`：增加"回测信号集 vs 逐日增量信号集"的一致性报告（当前已有 `crossval.py`，可产品化）

## 五、一个值得注意的方向（chan.py 的选择）

chan.py 没有停留在"用买卖点直接交易"，而是建了 **ML 框架（400+特征、XGB/LightGBM/AutoML）+ 线上线下一致性校验**——即**把缠论结构当作"特征"，而不是"信号"**，交给模型去学。

- 这个思路回避了"单个买卖点是否可靠"的问题
- **但注意：它同样绕不开我们发现的根本问题**——特征若含未来信息（如"事后bsp"），回测会虚高；若只用"当下可得"的特征（cbsp类），则优势大幅缩水
- 若要尝试，必须**先过我们的6道验收**（确认制 + 成本 + β对照 + 样本外），尤其β对照（A股宽基β≈0/负）

## 六、结论

1. **"信号延后/不可执行"是缠论量化的公认难题**——所有主流项目都意识到，chan.py 和 chanlun-pro 的文档写得非常清楚
2. **没有人解决"收益损失"这一层**：他们的做法是"放弃不可执行信号 / 逐bar增量 / 一致性校验 / 加其他指标辅助"，本质是**接受延迟、提高信号筛选质量**
3. **我们的"逐日确认制"与业界最佳实践同路线**（czsc 的顺序信号架构、chan.py 的 strict_open+judge_on_close 都是同一思想的实现），**且我们把收益归因做到了他们没有的深度**——这正是为什么只有我们得出了"该策略≈β"的结论
4. **借鉴价值**：三个机制（strict_open / judge_on_close / 一致性校验）可以吸收进我们的引擎；chan.py 的"缠论作特征+ML"是可探索的分支，但必须先过β对照这一关
