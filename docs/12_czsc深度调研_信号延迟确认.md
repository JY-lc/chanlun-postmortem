# czsc 深度调研报告：它是否解决了"信号延迟确认"问题？
**2026-09-10 · 源码级调研（czsc ★6087 + 其回测引擎 wbt）**

---

## 一、结论速览

| 层面 | czsc/wbt 的做法 | 是否解决 |
|---|---|---|
| **执行时点** | 权重在 bar t 生成 → **收益从 t+1 计入**；含 `fee_rate` 成本参数；内置 alpha 基准对照 | ✅ **解决**（比本项目原实现规范） |
| **缠论结构确认滞后** | 明确区分 `bi_list`（已完成笔）与 `ubi`（未完成笔），信号中**允许使用未完成笔**，但用 **"ub i长度≤7根K线"** 限制其使用 | ⚠️ **工程折中，未根治** |
| **信号主力** | 220+ 信号函数中大量是**当下可算的量价特征**（`bar.rs` 118KB），不以"需确认的缠论结构"为主 | ✅ **路线性规避**（不用就不会滞后） |

**一句话**：czsc 在"执行规范"上做得比我们原来好，但在"结构确认滞后"上**没有解决**——它选择了"限制使用未完成笔的长度"这种工程妥协，把风险降低而非消除。

---

## 二、证据一：分型识别同样需要右侧K线（与人我们的机制完全相同）

czsc 0.9.X `czsc/analyze.py`（Python实现，逻辑延续到 Rust）：

```python
def check_fx(k1: NewBar, k2: NewBar, k3: NewBar):
    """查找分型"""
    if k1.high < k2.high > k3.high and k1.low < k2.low > k3.low:
        fx = FX(symbol=..., dt=k2.dt, mark=Mark.G, high=k2.high, ..., elements=[k1, k2, k3])
```

- **分型的 `dt` 记在中间K线 k2 上，但成立需要 k3 存在** → 与本项目完全相同的"确认滞后"
- `check_fxs` 中还有异常兜底，说明其分型序列也会随新数据变化：
  ```python
  if len(fxs) >= 2 and fx.mark == fxs[-1].mark:
      logger.error(f"check_fxs错误: {bars[i].dt}，{fx.mark}，{fxs[-1].mark}")   # 同类分型相邻
  ```

## 三、证据二：明确区分"已完成笔 / 未完成笔"，并把选择权交给使用者

czsc 的 `CZSC` 对象同时暴露：

```python
@property
def ubi(self):
    """Unfinished Bi，未完成的笔"""
    ubi_fxs = self.ubi_fxs
    ...
```

- `bi_list` = **已确认的笔** → 安全，但**滞后**（等价于本项目的"定型日口径 = 2.11%"）
- `ubi` / `bars_ubi` / `ubi_fxs` = **未完成的笔** → 当下可见，但**可能被修正**（等价于本项目"分型确认日口径 = 6.83%，且含幻影信号"）
- **czsc 没有二选一地"解决"，而是两个都提供，交由使用者决策**

## 四、证据三：核心工程手段——限制"未完成笔"的长度（本报告最关键的发现）

czsc 的信号源码（Rust，`crates/czsc-signals/src/`）中反复出现同一模式：

**`byi.rs`（背驰辅助信号）**：
```rust
if c.bi_list.len() < 3 || c.bars_ubi.len() > 7 { return make_kline_signal_v1(&k1, k2, k3, "其他"); }
```
**`cxt.rs`（缠论信号，120KB）中 `cxt_bi_status_V230101`（笔表里关系）**：
```
信号逻辑：
1. 读取最新一笔方向；
2. 若最新笔为向下笔，当前状态记为 `向上`，反之记为 `向下`；
3. 若未完成笔长度 `bars_ubi` 大于等于 `bi_init_length`，记为 `中继`，否则记为 `转折`；
4. 笔数据不足时返回 `其他`。
...
if czsc.bi_list.len() < 3 || ubi_fxs.is_empty() { return ...("其他"); }
```

**模式总结**：
1. 允许使用**未完成笔**（不等到笔定型 → 减少滞后）
2. 但**限制其长度**（如 `bars_ubi.len() > 7` 则放弃 → 因为未完成笔走得越久，内部结构越复杂、越可能被修正）
3. 数据不足一律返回 **"其他"**（= 不产生信号，不交易）

→ 这是**工程妥协**：既不完全等确认（滞后7天），也不无限使用未确认结构（风险失控），而是"只在笔的早期（短笔）上做判断"。

## 五、关键对照：同类做法在本项目数据上的实测结果

czsc 的"允许未完成笔"路线 ≈ 本项目的 **B口径（分型确认日）**。我们用同一批数据、同一引擎实测过：

| 口径 | 含义 | 年化 | 夏普 | 说明 |
|---|---|---|---|---|
| **B 口径（≈czsc路线：分型确认即用）** | 允许用"刚确认"的结构 | **+6.83%** | 0.64 | 看起来不错 |
| **D 口径（严格：逐日截断验证+剔除幻影）** | 每个信号必须能在实盘当时被检出 | **+2.05%** | −0.15 | 真实可得 |
| C 口径（笔定型日，最严格） | 等反向分型确认笔成立 | +2.11% | −0.10 | — |

**B 与 D 的 4.8pp 差距从哪来？**
- 买点信号中 **24.8% 是"幻影信号"**：在全历史分析里存在，但在"逐日截断扫描"下**根本不出现**
- 这些幻影信号的特征恰恰是"事后看着完美、当时不可见"（即未完成笔被修正前的假象）
- **czsc 的"长度≤7"限制能减少这类风险，但无法消除**——因为它仍然在"分型确认后、笔定型前"就使用该结构，而这段时间正是笔可能被替换的窗口

## 六、czsc 真正值得借鉴的（3点）与不应照搬的（1点）

### ✅ 值得借鉴
1. **执行时点严格**：权重 t → 收益 t+1（wbt 文档明确："持仓收益计入后一个价格所在日"）+ `fee_rate` 成本参数 + 内置 **alpha 基准对照**（`alpha['超额'] = 策略 − 等权基准`）→ 这三条我们已经具备（T+1_open、SLIPPAGE、β对照），可对齐其"权重序列"这一更通用的抽象
2. **限制未完成结构的使用长度**：可作为我们引擎的一个**附加过滤器**（如"当前笔长度 > N 则不交易"），在我们已有确认制之上再加一层保护
3. **`信号 → 事件 → 持仓 → 操作` 分层架构**：signal/event/position/operate 四层解耦，比我们"信号直接驱动交易"更清晰，便于组合多信号（`signals_all/any/not`）

### ❌ 不应照搬
- **不要用"未完成笔"做信号**（czsc 的 cxt 类信号）：我们已实测这会引入幻影信号（B口径6.83% → 严格验证2.05%）。**必须用"逐日截断验证"作为最终防线**——这一点我们做得比 czsc 彻底

### ⚠️ 一个未解问题（czsc 也没答案）
czsc 从未公布过**经过完整验收**（确认制 + 成本 + β对照 + 样本外 + 多重检验）的实盘业绩。它的 `stats` 有丰富的指标（单笔盈亏比、日/周/月胜率、多头占比等），也有 alpha 对照，但**没有"必须显著超越基准"的硬门槛**。所以我们无法确认它的信号体系是否真的赚钱——这与本项目的结论一致：**回测指标丰富 ≠ 有可提取的α**。

---

## 七、总结

1. **czsc 没有解决"信号延迟确认"问题**——它的分型识别同样需要右侧K线（`check_fx(k1,k2,k3)`），机制与本项目完全相同
2. 它的应对是**三层工程妥协**：①执行层面严格（T+1、成本、alpha基准）②结构层面折中（允许未完成笔但限制长度≤7）③信号层面规避（主力用当下可算的量价特征）
3. **本项目的"逐日确认制"比 czsc 更彻底**：我们把"确认滞后的收益影响"量化到了具体数字（16.79%→2.05%），并强制剔除幻影信号；czsc 则停留在"降低风险"的工程层面
4. **这再次印证**：确认滞后是缠论结构的内在性质（分型必须等右侧K线），**没有任何开源项目真正解决了它**——区别只在于"是否意识到、以及是否量化了影响"
