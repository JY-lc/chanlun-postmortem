## 一、长度过滤器实测（czsc 路线移植）—— ❌ 无效

czsc 源码：`if c.bars_ubi.len() > 7 { return "其他" }`（未完成笔过长则不判断）
本实验：在确认制信号上计算"信号日时当前笔已走交易日数"，超阈值则跳过：

| 阈值 | 年化 | 夏普 | 买入笔数 |
|---|---|---|---|
| 基线（不过滤） | +2.05% | −0.15 | 103 |
| ≤20 | +2.05% | −0.15 | 103 |
| ≤15 | +2.05% | −0.15 | 103 |
| ≤10 | +2.22% | −0.12 | 101 |
| **≤7（czsc 默认值）** | +2.03% | −0.16 | 97 |
| ≤5 | +1.98% | −0.17 | 96 |

**结论：无效**（阈值≤15完全无变化，≤10仅+0.17pp噪声级，czsc默认值≤7反而略降）。
**原因**：我们的确认制信号本身就产生在"分型刚确认"时（笔长天生很短，多数≤10），所以"限制未完成笔长度"没有区分度。
**czsc 需要这个过滤器，是因为它在每根K线上都可能用未完成笔判断；而我们已经比它严格一档。**

## 二、chan.py（★2071）内容详解

### 2.1 最重要的前提：**核心代码不开源**

> README 原文："当前公开部分代码**暂时只包含基本的静态计算能力**，暂未包含**策略类，特征，模型，automl框架，交易引擎对接**等；完整代码22000行左右，**公开版约5300行**"

**即：想借鉴它的策略/特征/ML/实盘代码，公开仓库里没有。** 只能看文档描述的**设计思想**。

### 2.2 四层能力（文档描述）

| 层级 | 内容 |
|---|---|
| ① 基本元素计算 | 分型/笔/线段/中枢/买卖点（可继承基类自定义）、**多级别联立**、**区间套**、MACD/均线/布林/Demark、多数据源（futu/akshare/baostock）、绘图/回放/API服务 |
| ② 策略买卖点 | **形态学买卖点 bsp** + **自定义动力学买卖点 cbsp** + 可配置背驰算法 |
| ③ 机器学习 | 对买卖点打分：**400+特征**、5种标签、XGB/LightGBM/MLP、**AutoML超参搜索**、回测评估框架 |
| ④ 线上交易 | Futu对接（模拟+实盘）、实时数据（sina/pytdx/futu/akshare）、mysql/sqlite、**线上线下特征一致性校验** |

### 2.3 ⭐ 它处理"信号延迟确认"的真实方案（原文，最有价值）

**`## 交易系统 → 典型流程`**：
```
- 检测信号是否突破
    - 如果突破：检测模型分数是否高于指定阈值，是则开仓
- 对于开仓结果进行后验：比如对于天级别的交易，交易时当天K线肯定还没完成（！），
  所以需要在K线完成后重新检查是否突破和分数阈值
    - 如果后验校验没问题：持续更新股价，是否触达止损、止盈或者平仓买卖点产生
    - 如果后验有问题：下一个周期马上以最快的速度卖出，无论是否盈利
```

**这就是它的答案：不等确认，而是"先开仓 + 日终后验 + 失败立即撤"。**

配套机制：
- `bsp_signal(chan, lv)`：返回"当前数据哪些股票**可能在第二天如果满足自定义的突破条件时**"→ **T日筛候选、T+1日突破确认后才开仓**（条件单式）
- `judge_on_close=True`："根据K线收盘价来作为开/平仓指标，默认为True（否则当天K线某一时刻突破了信号阈值即会交易）"→ **明确防"盘中瞬时突破"的伪信号**
- `strict_open=True`："如果对一个买卖点当下无法找到合适的买卖时机却已经完成一笔了，就放弃"
- `FeatureReconciliation.py`：官方承认"**backtest.py 中笔段的计算起始时间和实盘中的不一样，可能会导致某些特征不相等**"→ 专门做线上线下特征一致性校验

### 2.4 作者自承的关键难点（"其他不值一提的优化"）

原文列出的**未展开**问题里，前几条正是我们的核心关注：
- **如何防止特征穿越**
- 保证在线离线回测特征一致性校验原理
- 如何保证交易流程调度顺序正确性
- 交易脚本重启如何恢复现场
- 如何检测大小级别K线数据不一致

→ **它意识到这些问题，但方法不公开（在完整版/商业部分）**

### 2.5 实盘验证情况（诚实但有限）

- 模拟盘/实盘运行**2个月、零人工干预**
- 无专门仓位控制："买的手数为让开仓金额大于 bench_price 的最小值，模拟盘10000，实盘2000"
- 作者坦言："富途评估收益率的分母是总模拟金额100万，所以**在仓位不高的情况下收益率显示总是很低**"
- **没有公布可信的年化/夏普数字**（只有实验效果图）

### 2.6 区间套策略示例（文档给出的完整代码，20行）

父级别买卖点 + 次级别一类买卖点共振（`chan[lv+1]` 拿次级别数据、`sup_kl` 回溯父级别K线）：

```python
def try_open(self, chan, lv):
    data = chan[lv]
    if lv != len(chan.lv_list)-1 and data.bi_list:
        if qjt_bsp := self.cal_qjt_bsp(data, chan[lv + 1]):
            return qjt_bsp
# cal_qjt_bsp: 父级别买卖点当日 + 次级别出现一类买卖点 → 返回区间套买卖点
```

→ **这正是你材料里3.5测过的"小级别共振"**——chan.py 把它作为标准能力提供，但**没有给出有效性验证**（我们实测过：负价值）。

## 三、三种处理路线对比（含我们的实测数据）

| 路线 | 做法 | 我们的实测 | 出处 |
|---|---|---|---|
| **A. 严格等确认** | 等笔定型才交易（剔除幻影信号） | **年化 2.05%**、夏普−0.15 | 我们的"逐日确认制" |
| B. 不验证直接交易 | 按"当下结构"直接买卖 | 年化 6.83%、夏普0.64（**含24.8%幻影信号，不可实现**） | 我们的B口径 ≈ czsc的ubi用法 |
| **C. 先开后验** | **盘中先开仓 → 日终后验 → 失败次日即撤** | **未测（chan.py的方案）** | chan.py 典型流程 |
| D. 长度过滤 | 未完成笔过长则不判断 | 无效（本报告第一节） | czsc |

**关键洞察**：我们只测了 A（等确认）和 B（不验证）两端，**chan.py 的 C 方案（先开后验）恰好是两者之间的第三条路，且是我们尚未实测的**——它的逻辑是"用快速纠错换取进场时机"，理论上能在"避免滞后"与"控制幻影损失"之间取得平衡。

## 四、建议的下一步（可立即实测）

**模拟 chan.py 的 C 方案**（用现有框架，成本低）：
1. 按"当下可见结构"（我们的B口径）在 T+1 开盘买入
2. **T+1 收盘后做后验**：用完整K线重算 → 若信号不成立（幻影）→ T+2 开盘无条件卖出
3. 其余信号正常持有（走现有止损/止盈）
4. 对比 A（2.05%）/ B（6.83%）/ C

若 C 能显著优于 A，说明 chan.py 的路线在这个数据条件下有效，值得进一步工程化。
